# Renamer App — V1.0.0 UI/UX Refactor Plan

## 0. Development Workflow Rule

**NO database migrations.** This is a dev-mode app. Never use Nextcloud's migration system.

- Schema changes are applied manually or via disable/enable cycles.
- To reset the app to a clean state: disable the app in Nextcloud, then re-enable it.
- If the `renamer_rules` table exists from a previous iteration and causes issues, drop it manually before re-enabling.

Branch: `V1.0.0`

---

## 1. Current Architecture Summary

### 1.1 Services
- `lib/Service/RuleService.php` — rule CRUD, import/export, default rules fallback
- `lib/Service/RenameService.php` — rename execution, collision detection
- `lib/Service/PreviewService.php` — preview generation per mode
- `lib/Service/MetadataService.php` — audio metadata extraction using ffmpeg

### 1.2 Persistence
- `lib/Db/Rule.php` — entity with `getFieldTypes()` override
- `lib/Db/RuleMapper.php` — QBMapper for `renamer_rules` table
- Table: `oc_renamer_rules` (created manually, no migrations)

### 1.3 API Routes
- `GET /api/rules` — list user + default rules
- `POST /api/rules` — create rule
- `PUT /api/rules/{id}` — update rule
- `DELETE /api/rules/{id}` — delete rule
- `POST /api/rules/import` — import JSON
- `GET /api/rules/export` — export JSON
- `POST /api/metadata/preview` — metadata preview for audio files
- `POST /rename` — execute rename

### 1.4 Frontend (current)
- `js/rename.js` — single-panel modal, vanilla JS, inline CSS injection, all logic in closure
- `js/utils.js` — extracted pure functions (computeNewName, sequence, splitNameAndExt, computePreview, etc.)
- No framework, no build step, no templates

## 2. New UI/UX Architecture

### 2.1 Modal Structure (Fullscreen-capable)

This remains a **modal dialog** opened from Nextcloud's file action / toolbar.

- Opens **fullscreen by default** inside the browser viewport (no modal overlay, no max-width/height constraints).
- Top-right corner: **Réduire** button.
- Clicking it transitions to a **compact/minimized** panel (~90vw/90vh centered).
- Button toggles: **Réduire** ↔ **Agrandir**.
- All transitions use `ease-in-out` with duration ~300ms.
- State persisted in memory (not localStorage).
- Still opened via Nextcloud file action / toolbar button, exactly like today.

### 2.2 Top Navigation (Future-Proof)

- A top bar will host navigation tabs for future tools:
  - **Advanced files & Folder renaming** (default tab, implemented in V1.0.0)
  - **Files metadata renaming** (future placeholder)
  - Other tabs added later
- Switching tabs uses smooth `ease-in-out` transition.

#### 2.3.2 Files Section (Top)

- Horizontal scrollable list of selected files.
- Each file is a draggable pill/tag.
- HTML5 drag-and-drop reordering.
- Drop updates internal `files` array and triggers preview refresh.
- At least one file required; show empty state message if none.

#### 2.3.3 "+" Button & Rule Creation Popup

- Centered or left-aligned in the rules panel: large circular button with a **"+"** inside.
- Circle border: **Nextcloud blue** (`#0082c9`).
- Click opens a popup/dropdown with rule type choices:
  - **Search & Replace**
  - **Séquence**
  - **Regex**
  - **File Type Filter**
- Each choice is a styled card/button with icon + label.
- After selecting a type, a new rule card appears at the bottom of the rules list with default values pre-filled.

### 2.4 Files Metadata Renaming Tab (future)

- Second tab inside the modal.
- Dedicated UI for audio/video metadata-based renaming.
- Reuses `MetadataService` backend.
- Not implemented in V1.0.0 — placeholder tab only.
- Switching tabs uses the same `ease-in-out` transition as fullscreen/collapse.

### 2.5 Rule Types

#### 2.5.1 Search & Replace
- Fields: **Chercher** (text input), **Remplacer par** (text input)
- Target scope: 3 toggle buttons — **Nom complet**, **Extension**, **Nom sans extension**

#### 2.5.2 Séquence
- Sub-type select: **Numérique** (1, 2, 3...), **Alphabétique** (a, b, c...), **Romain** (I, II, III...)
- For Numeric: zero-padding option (e.g., `3` → `001, 002, 003`)
- Start value input (default: 1)
- Separator input (default: ` - `)
- Target scope: same 3 toggles

#### 2.5.3 Regex
- Fields: **Motif** (text input with regex validation), **Remplacement** (text input)
- Real-time regex syntax validation (green/red indicator)
- Target scope: same 3 toggles

#### 2.5.4 File Type Filter
- Displays a preview of all unique file extensions found in the selected files list
- Each extension is shown as a clickable pill/tag
- Clicking an extension toggles its selection (selected = highlighted)
- A toggle switch at the top: **Ignored** (default) / **Only**
  - **Ignored mode**: files with selected extensions are excluded from rename operations
  - **Only mode**: only files with selected extensions are processed; others are skipped
- The rule card shows the count of selected extensions
- No target scope needed (this rule acts as a filter before other rules)

### 2.6 Rule Card Design

Each rule is a self-contained card (border-radius: 8px) with:

- **Left colored border** (4px) matching rule type:
  - Search & Replace: `#0082c9` (Nextcloud blue)
  - Séquence: `#f0a030` (orange)
  - Regex: `#e02020` (red)
  - File Type Filter: `#22c55e` (green)
- **Header row**:
  - Left: drag handle icon (⠿ or SVG `⋮⋮`), then **numbered badge** (background = border color, white text)
  - Center: rule name (editable inline or shown in body)
  - Right controls:
    - **Toggle on/off** (slider switch, default ON)
    - **Duplicate** icon button
    - **Delete** icon button
    - **"..."** (more) button → opens advanced options dropdown
- **Body**: rule-specific fields (pattern, replacement, sub-type, etc.)
- **Target scope buttons**: 3 small toggle buttons at bottom of card (not shown for File Type Filter)
  - Nom complet | Extension | Nom sans extension
  - Visual state: active = filled, inactive = outline
- When toggled OFF: entire card transitions to grayscale (opacity 0.5, filter grayscale) with `ease-in-out 300ms`.

### 2.7 Advanced Options ("..." menu)

Dropdown with:
- **Sauvegarder** — save rule for all users (calls `/api/rules` with `isDefault: true`)
- **Dupliquer**
- **Supprimer**
- **Activer / Désactiver** (text versions of the toggle)
- **Renommer la règle** — inline edit of rule name

### 2.8 Preview Panel (Right Side)

- Header: **Aperçu** with future toggle: **Flat** / **Dossiers** (for subfolder navigation)
- List of files showing:
  - Left: original filename (or path)
  - Arrow/divider
  - Right: new filename (or path)
- Green highlight on changed parts, red strikethrough on removed parts
- Updates live on any rule change
- If no rules or all rules OFF: shows original names unchanged
- Clicking a file row could expand to show full path (future)

### 2.9 Global Actions

- Bottom of preview panel or top of rules panel:
  - **Tout activer** / **Tout désactiver** toggle buttons
  - **Réinitialiser** (remove all rules)

## 3. Backend Changes

### 3.1 Remove Dry Run
- `RenameService::execute()`: remove `dryRun` parameter.
- Always compute operations, always perform the rename.
- Return `{ success, renamed, skipped, errors }` — no dry-run mode.
- `PreviewService` remains for the preview panel (server-side validation).

### 3.2 Remove Dev Mode
- Remove `dev` parameter from `/rename` endpoint.
- Remove bash output from `PreviewService::generate()`.
- Remove dev mode logic from frontend entirely.

### 3.3 New/Updated Endpoints

| Method | Route | Purpose |
|--------|-------|---------|
| POST | `/api/rules` | create rule (add `target` field: `full`, `extension`, `name`) |
| PUT | `/api/rules/{id}` | update rule |
| DELETE | `/api/rules/{id}` | delete rule |
| POST | `/api/rules/import` | import JSON |
| GET | `/api/rules/export` | export JSON |
| POST | `/rename` | execute rename (no dry-run, no dev) |

### 3.4 Rule Entity Updates

Add fields to `lib/Db/Rule.php`:
- `target` — string enum: `full`, `extension`, `name` (default: `full`)
- `sequenceType` — string enum: `numeric`, `alphabetic`, `roman` (for sequence rules)
- `startValue` — int (for sequence rules)
- `zeroPadding` — int (for numeric sequence, default: 0)
- `enabled` — bool (default: true)
- `filterMode` — string enum: `ignored`, `only` (for filetype rules, default: `ignored`)
- `extensions` — JSON array of strings (for filetype rules)

Update `RuleMapper` accordingly.

Note: For `extensions` JSON field, use `json_encode`/`json_decode` in PHP. The DB column type should be `text` or `json` depending on DB engine.

### 3.5 Utils Object (Backend)

Create `lib/Service/Utils.php` (or keep as static methods) containing:
- `computeNewName(string $name, string $mode, string $pattern, string $replacement, ...): string`
- `applyIncrement(string $baseName, int $index, string $incSep, string $incFormat): string`
- `sequenceGenerate(int $index, string $type, int $start, int $padding): string`
- `extractExtension(string $filename): array{name, extension}`
- `escapePath(string $path): string`

Used by both `RenameService` and `PreviewService` to eliminate duplication.

### 3.6 Remove PreviewService

Merge `PreviewService::computeNewName()` into `RenameService::computeNewName()` and `Utils`.
`RenameService::execute()` can still return a preview-like structure for the frontend, or we keep `PreviewService` as a thin wrapper. Since the frontend does live preview client-side, the server preview endpoint becomes optional.

## 4. Frontend Changes

### 4.1 File Structure

```
js/
├── rename.js          → replaced by new modular structure
├── utils.js           → extracted pure functions (computeNewName, sequence, etc.)
├── app.js             → main entry point, state management
├── components/
│   ├── RuleCard.js    → single rule card component
│   ├── RuleForm.js    → popup for creating new rule
│   ├── Preview.js     → preview panel component
│   ├── FilesBar.js    → top draggable files bar
│   └── Toggle.js      → reusable on/off toggle switch
└── style.js           → all CSS injected as string (or switch to separate CSS file)
```

### 4.2 Utils.js — Extracted Functions

Move all pure functions from current `rename.js` into `utils.js`:

```javascript
const RenamerUtils = {
    escapeHtml(str) { ... },
    escapePath(path) { ... },
    computeNewName(name, mode, pattern, replacement, options) { ... },
    sequenceGenerate(index, type, start, padding) { ... },
    splitNameAndExt(filename) { ... },
    applyTargetScope(name, ext, target) { ... },
    // diff highlighting helpers
    computeOriginalDiff(original, mode, pattern) { ... },
    computeNewDiff(original, transformed, mode, pattern, replacement) { ... },
    // file type filter helpers
    getUniqueExtensions(files) { ... },
    computePreview(files, rules) { ... },
};
```

### 4.3 State Management

```javascript
const state = {
    files: [],           // array of file paths
    rules: [],           // array of rule objects
    isFullscreen: true,  // layout mode
    isLoading: false,
    activeTab: 'advanced', // 'advanced' | 'metadata'
};
```

### 4.4 Rule Object Schema

```javascript
{
    id: string | number,
    type: 'search_replace' | 'sequence' | 'regex' | 'filetype',
    name: string,
    enabled: boolean,
    target: 'full' | 'extension' | 'name', // not used for filetype
    // search_replace fields
    pattern: string,
    replacement: string,
    // sequence fields
    sequenceType: 'numeric' | 'alphabetic' | 'roman',
    startValue: number,
    zeroPadding: number,
    separator: string,
    // regex fields
    regexPattern: string,
    regexReplacement: string,
    // filetype fields
    filterMode: 'ignored' | 'only',
    extensions: string[], // selected extensions
    // metadata
    isDefault: boolean,
}
```

### 4.5 CSS Architecture

- Define CSS custom properties for Nextcloud theme colors:
  ```css
  :root {
      --nc-blue: #0082c9;
      --nc-blue-hover: #00619a;
      --nc-bg: var(--color-main-background, #fff);
      --nc-text: var(--color-main-text, #000);
      --nc-border: var(--color-border, #ccc);
      --nc-radius: var(--border-radius-large, 8px);
      --nc-transition: all 300ms ease-in-out;
  }
  ```
- Use CSS Grid for the main layout (rules | preview).
- Use Flexbox for internal card layouts.
- All interactive elements get `transition: var(--nc-transition)`.

### 4.6 Drag & Drop (Rules Reordering)

- Each rule card has a drag handle (⠿ SVG).
- SortableJS is NOT used (avoid external deps). Implement with native HTML5 DnD:
  - `dragstart`: set data, add `dragging` class
  - `dragover`: prevent default, show drop indicator
  - `drop`: reorder array, re-render, update numbering
- After drop: renumber all rule cards sequentially (1, 2, 3...).

### 4.7 Remove Old Modes

From the mode select and from `computeNewName`:
- Keep: `regex`, `replace`, `sequence` (new), `cascade`, `camelcase`, `snakecase`, `removespaces`, `capitalizefirst`, `capitalizewords`, `metadata`
- Remove: `dev mode` checkbox, `dry run` checkbox

### 4.8 Preview Logic

- Frontend computes preview using `RenamerUtils.computeNewName()` for each file × each enabled rule (in order).
- Preview shows: `originalPath → newPath` with diff highlighting.
- Updates on:
  - Any rule field change
  - Rule toggle (enable/disable)
  - Rule reorder
  - File list change
